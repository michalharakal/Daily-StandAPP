**Doc status (2026-04-30): §5.2 (LLM Module) describes a `JavaAgentLoop` + `JavaTool` tool-calling architecture that was rolled back during validation.** Llama 3.2 1B Q8_0 cannot reliably emit the strict tool-call JSON the Llama 3 chat template requires. The runtime now uses `KLlamaSession.generate()` directly with a manually-formatted Llama 3 turn prompt; commits are pre-fetched in the CLI. The three `JavaTool` wrapper classes shown in the diagrams below were deleted. Tool calling will be re-introduced when a stronger embedded model lands. See plan `continue-with-general-effort-groovy-coral.md` §V8.2 / §V8.3.

== 5.2 Module: llm (Level 2)

The LLM module provides AI inference with a pluggable architecture. Two
backends are available, selected via `MCP_LLM_BACKEND` (default: `SKAINET`).
The SKAINET backend itself has two paths: the default single-shot
`SKaiNetLLMService` (raw `KLlamaSession.generate`) and the opt-in
`ToolCallingLLMService` (driven by `JavaAgentLoop` from `skainet-transformers`),
gated by `STANDAPP_TOOL_CALLING=1`.

=== Key Classes

[cols="1,3"]
|===
|Class |Description

|`LLMService`
|JVM interface for pluggable backends: `generate(prompt, maxTokens, temperature, topP): String`

|`LLMServiceFactory`
|Factory that instantiates the right `LLMService` based on `MCP_LLM_BACKEND` (defaults to `SKAINET`). For `SKAINET` it calls `EmbeddedModelLoader.extract()` unless `MCP_LLM_MODEL_PATH` overrides.

|`LLMBackendType`
|Enum: `SKAINET` (default), `REST_API`.

|`LLMConfig`
|Data class for programmatic backend configuration (modelPath, baseUrl, modelName, apiKey)

|`SKaiNetLLMService`
|Default SKAINET path. Wraps a `KLlamaSession`; `generate()` calls
`session.generate(wrappedPrompt, config)` once. Wrapping is `formatLlama3Turn`
inline (the chat template is hand-rolled, not delegated to SKaiNET-transformers).
Emits `[STAGE/...]` logs for system/user/wrapped prompts, prefill TTFT, and
final answer. Implements `AutoCloseable`.

|`ToolCallingLLMService`
|Opt-in SKAINET path (`STANDAPP_TOOL_CALLING=1`). Wraps a `KLlamaSession` +
a `JavaAgentLoop` from `skainet-transformers`. `generate()` registers tools,
renders the round-0 chat template for inspection, and delegates to
`agent.chat(prompt, tokenConsumer)`. Logs every observable transition under
`[STAGE/...]`. Implements `AutoCloseable`.

|`GetRecentCommitsTool`
|`Tool` (SKaiNET-transformers public interface) wrapping `getAllCommitsInPeriod`
/ `commitsByAuthorAndPeriod` from the `data` module. Schema: `{days: int,
author?: string}`. The repo path is captured at construction time, never asked
of the model. Caps results at 50 commits and emits `[GitTool]` log lines.

|`EmbeddedModelLoader`
|Locates `models/Llama-3.2-1B-Instruct-Q8_0.gguf` on the classpath and extracts it to `~/.cache/standapp/models/` on first launch (idempotent — skipped when the cached file size matches the resource).

|`RestApiLLMService`
|OpenAI-compatible REST endpoint client (works with Ollama, llama.cpp server, LM Studio, vLLM). Always single-shot — no tool calling.
|===

NOTE: New backends can be added by implementing the `LLMService` interface and
registering them in `LLMServiceFactory`. New tools for the opt-in path can be
added by implementing `sk.ainet.apps.kllama.chat.Tool` and passing them to
`ToolCallingLLMService.create(modelPath, tools=…)`.

== 5.4 Module: mcp-server (Level 2)

The MCP server exposes git functionality to *external* AI assistants via the Model Context Protocol. These MCP-protocol tools are distinct from the LLM agent-loop tools described in §5.2 — both surfaces use the same JGit functions (`commitsByAuthorAndPeriod`, `getAllCommitsInPeriod`) underneath, but `mcp-server` serialises them as JSON-RPC for remote clients while the `llm` module wraps them as `JavaTool` instances for the embedded model.

|`LocalAIServer`
|`cloud-api:server`
|Ktor-based server exposing `/v1/chat/completions` and `/v1/models` endpoints

|`LlmClient`
|`cloud-api:client`
|HTTP client with `chatCompletion()` and `listModels()` methods

|`AgentMain`
|`cloud-api:agent`
|Koog AIAgent that starts the local server and runs agent interactions
|===
