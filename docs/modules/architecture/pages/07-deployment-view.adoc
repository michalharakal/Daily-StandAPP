== 7.1 Infrastructure Overview

The CLI is now a *self-contained* fat JAR: the Llama 3.2 1B Instruct (Q8_0, ~1.3 GB) GGUF is embedded as a JAR resource, so end-users do not need to manage external model files. On first run, `EmbeddedModelLoader` extracts the GGUF to `~/.cache/standapp/models/` (idempotent — extraction is skipped when the cached file size matches the resource).

== 7.3 MCP Server Deployment

=== Claude Desktop Configuration

Add to Claude Desktop's MCP configuration (`claude_desktop_config.json`):

[source,json]
----
{
  "mcpServers": {
    "standapp-git": {
      "command": "java",
      "args": [
        "--add-modules", "jdk.incubator.vector",
        "-Dllm.model=/path/to/model.gguf",
        "-jar",
        "/path/to/mcp-server-jvm.jar"
      ]
    }
  }
}
----

== 7.4 Docker Deployment

A `Dockerfile` and `docker-compose.yml` are provided for containerized deployment.

[source,bash]
----
# Build and run with Docker Compose
docker compose build
docker compose up
----

The Docker image uses a multi-stage build with JDK 21 and packages the MCP server fat JAR.

== 7.5 Environment Variable Configuration

End users do not need any environment variables — `SKAINET` is the default backend and the model is embedded. Variables exist only as overrides.

[cols="1,2,2"]
|===
|Variable |Default |Description

|`MCP_LLM_BACKEND`
|`SKAINET`
|Backend selection: `SKAINET` (embedded Llama 3.2 1B) or `REST_API`.

|`MCP_LLM_MODEL_PATH`
|_(unset → use embedded resource)_
|Optional override. Set to an absolute GGUF path to use a different model on the SKAINET backend. The embedded model wins when this is unset.

|`MCP_LLM_REST_BASE_URL`
|`http://localhost:11434`
|Base URL for REST API backend

|`MCP_LLM_REST_MODEL`
|`llama3.2:3b`
|Model name for REST API backend

|`MCP_LLM_REST_API_KEY`
|_(optional)_
|Bearer token for authenticated REST API endpoints
|===

== 7.6 Embedded Model

The repo ships a build-time hook that downloads the GGUF *into the source tree* before the JAR is assembled.

* Source: `bartowski/Llama-3.2-1B-Instruct-GGUF` on Hugging Face (filename `Llama-3.2-1B-Instruct-Q8_0.gguf`).
* Build script: `scripts/download-model.py` (PEP 723 inline-deps; runs as `uv run scripts/download-model.py`).
* Drop location: `llm/src/jvmMain/resources/models/Llama-3.2-1B-Instruct-Q8_0.gguf` (gitignored).
* Gradle wiring: a `prepareModel` `Exec` task in `llm/build.gradle.kts` invokes the uv script and is a dependency of `jvmProcessResources`. `onlyIf { !modelFile.exists() }` keeps reruns cheap.
* Runtime: `EmbeddedModelLoader.extract()` copies the resource to `~/.cache/standapp/models/` (random-access on disk is required by `KLlamaJava.loadGGUF`).

[cols="1,2,3"]
|===
|Aspect |Requirement |Notes

|Format
|GGUF
|Q8_0 chosen for size/quality trade-off (~1.3 GB).

|Architecture
|Llama 3.2
|Auto-detected by SKaiNET-transformers; chat template is `llama3`.

|First-run extraction
|`~/.cache/standapp/models/`
|~5-15 s on local disk; idempotent on subsequent runs.

|Override
|`MCP_LLM_MODEL_PATH=/path/to/other.gguf`
|Lets power users swap in a larger model without rebuilding the JAR.
|===
