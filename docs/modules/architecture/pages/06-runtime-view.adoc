== 6.1 MCP Tool Call: Get Commits by Author

This scenario shows how an AI assistant retrieves commits for a specific author.

[mermaid]
----
sequenceDiagram
    participant Client as MCP Client<br/>(Claude)
    participant Transport as StdioTransport
    participant Server as MCP Server
    participant Handler as Tool Handler
    participant Git as GitClient
    participant Repo as Git Repository

    Client->>Transport: tools/call<br/>{tool: "get_commits_by_author"}
    Transport->>Server: dispatch request
    Server->>Handler: invoke tool

    Handler->>Handler: parse arguments<br/>(repoDir, author, dates)
    Handler->>Handler: parse ISO dates to Instant

    Handler->>Git: commitsByAuthorAndPeriod()
    Git->>Repo: Git.open(repoDir)
    Git->>Repo: git.log().call()
    Repo-->>Git: RevCommit[]

    Git->>Git: filter by author & dates
    Git->>Git: map to GitInfo

    Git-->>Handler: List<GitInfo>

    Handler->>Handler: format as text
    Handler-->>Server: CallToolResult
    Server-->>Transport: JSON response
    Transport-->>Client: tool result
----

== 6.2 LLM Standup Summary — Two-Model Pipeline (SKAINET, default)

The default CLI flow. `standupFlow { }` builds a SKaiNET `DataPipeline`
(`[PIPELINE] qwen-commits -> require-commits -> preprocess -> summarize[prompt -> llama -> parse xN]`);
the CLI does not pre-fetch commits — Qwen3-0.6B turns the request into one
`get_recent_commits` tool call, the tool records the structured commit list,
and Llama-3.2-3B-Instruct writes the summary from the engine's prompt
templates. See §8 (Crosscutting Concepts) for chat templates, tool-call
processing and the stage-log vocabulary.

[mermaid]
----
sequenceDiagram
    participant User
    participant CLI as StandAPP-cli
    participant Flow as DataPipeline<br/>(standupFlow)
    participant Provider as ModelProvider<br/>(releasing)
    participant QStage as QwenCommitsStage
    participant Agent as AgentLoop<br/>(QwenChatTemplate, 1 round)
    participant Qwen as Qwen3-0.6B Q8_0
    participant Tool as RecordingGitCommitsTool
    participant Git as JGit (data module)
    participant Sum as RetryingSummarizeStage
    participant LStage as LlamaGenerateStage
    participant Llama as Llama-3.2-3B Q4_K_M

    User->>CLI: standapp --repo R --days 7
    CLI->>Flow: execute(StandupRequest(R, days=7))
    Flow->>QStage: process(request)
    QStage->>Provider: withModel(QWEN3_0_6B)
    Note over Provider: resolve path (cache / download),<br/>log [MODEL] + [MODEL LOAD]
    QStage->>Agent: runWithEncoder(system + user, listener)
    Note over QStage: log [STAGE/QWEN], [STAGE/QWEN RENDERED PROMPT]
    Agent->>Qwen: prefill (batched 64) + greedy decode, ≤192 tokens
    Qwen-->>Agent: <tool_call>{"name":"get_recent_commits","arguments":{"days":7}}</tool_call>
    Note over Agent: log [STAGE/QWEN PREFILL DONE], [STAGE/QWEN RESPONSE],<br/>[STAGE/TOOL CALLS]
    Agent->>Tool: execute({days:7})
    Tool->>Git: getAllCommitsInPeriod(R, now-7d, now)
    Git-->>Tool: List<GitInfo>
    Note over Tool: recorded = commits<br/>log [GitTool] result: n commit(s) recorded
    Tool-->>Agent: "ok: n commit(s) found in the last 7 day(s)"
    Note over Agent: maxToolRounds = 1 → return,<br/>no second generation
    Agent-->>QStage: (log [STAGE/TOOL RESULT], [STAGE/QWEN COMPLETE])
    Provider-->>QStage: close Qwen (log [MODEL] released)
    QStage-->>Flow: CommitBatch(source = QWEN_TOOL_CALL)

    Flow->>Flow: require-commits (log [STAGE/COMMITS])<br/>preprocess: shortIds(7), firstMessageLine(120), limit(60)

    Flow->>Sum: process(CommitBatch)
    Sum->>Sum: PromptStage → system + user prompt (log [STAGE/PROMPT])
    loop until parse succeeds or attempts exhausted
        Sum->>LStage: process(PromptedBatch)
        LStage->>Provider: withModel(LLAMA_3_2_3B)
        Note over Provider: log [MODEL] + [MODEL LOAD]
        LStage->>Llama: Llama3ChatTemplate render → generateUntilStop<br/>(stop {<|eot_id|>, <|end_of_text|>}, temp 0.1, top-p 0.9 / top-k 40)
        Note over LStage: log [STAGE/INPUT], [STAGE/SYSTEM PROMPT], [STAGE/USER PROMPT],<br/>[STAGE/PREFILL …], [STAGE/PREFILL DONE]
        Llama-->>LStage: streamed tokens → onToken (stdout for --format md)
        Note over LStage: log [STAGE/COMPLETE], [STAGE/FINAL ANSWER]
        Provider-->>LStage: close Llama (log [MODEL] released)
        Sum->>Sum: SummaryParser.parse (log [STAGE/PARSE] on rejection)
    end
    Sum->>Sum: QualityScorer.score (with --score)
    Sum-->>Flow: PipelineResult
    Flow-->>CLI: result
    CLI-->>User: rendered summary (md | json | text), score report on stderr
----

[NOTE]
====
*Fallback.* If Qwen produces no usable call — no `<tool_call>`, a call that
fails JSON-schema validation (`[STAGE/TOOL VALIDATION FAILED]`), an exhausted
token budget or an exception — `QwenCommitsStage` logs
`[STAGE/FALLBACK] Qwen did not produce a usable get_recent_commits call (…); fetching commits directly`
and delegates to `GitCommitsStage`; the batch is tagged `DIRECT_FALLBACK` and
the summary is still produced. A git failure inside the tool is re-raised as
`GitAccessException` (exit code 3).
====

[NOTE]
====
*Direct git path.* `--since/--until` (the tool is day-based), `--commits git`
and the `REST_API` backend skip Qwen: `GitCommitsStage` fetches the window
through JGit (`[STAGE/GIT]`) and the rest of the pipeline is unchanged. With
`REST_API` the summariser is `LLMServiceGenerateStage(RestApiLLMService)`.
====

== 6.3 First Run — Model Resolution and Loading

No model is bundled in the JAR. Each stage asks the `ModelProvider` for its
model; `ModelResolver` turns the `ModelSpec` into a local file, downloading
through SKaiNET's `hf://` data-source resolver on a cold cache
(~0.6 GB + ~2.0 GB, once per machine).

[mermaid]
----
sequenceDiagram
    participant Stage as Qwen / Llama stage
    participant Provider as ModelProvider
    participant Resolver as ModelResolver
    participant DS as JvmDataSourceResolver<br/>(skainet-data-source, Ktor CIO)
    participant HF as huggingface.co
    participant Cache as $STANDAPP_MODEL_CACHE_DIR<br/>(~/.cache/standapp/models)
    participant Local as LocalModel.load

    Stage->>Provider: withModel(spec)
    Provider->>Resolver: resolve(spec, explicitPath?)

    alt --qwen-model / --llama-model flag
        Resolver-->>Provider: local file (or hf://|https:// URI → download branch)
    else STANDAPP_QWEN_MODEL_PATH / STANDAPP_LLAMA_MODEL_PATH<br/>(or legacy MCP_LLM_MODEL_PATH, Llama only)
        Resolver-->>Provider: local file
    else catalog hf:// URI
        Resolver->>DS: resolve(DataSourceRequest(uri, CachePolicy.Use | Offline))
        alt cache hit
            DS-->>Resolver: localPath (log [MODEL] cache hit)
        else STANDAPP_OFFLINE=1
            DS-->>Resolver: DataSourceException → CLI exit 4
        else first run
            DS->>HF: GET GGUF (HF_TOKEN if set)
            HF-->>DS: bytes (log [MODEL] downloading … every 64 MB)
            DS->>Cache: store
            DS-->>Resolver: localPath (log [MODEL] downloaded, size sanity check)
        end
    end

    Provider->>Local: load(spec, path)
    Note over Local: KernelSetup.ensureInstalled()<br/>KernelPacks.install() + FfmRowMajorKernelPack.install()<br/>(libskainet_kernels.so extracted to java.io.tmpdir)
    Local->>Local: StreamingGGUFReader → ModelMetadata, TokenizerFactory
    Local->>Local: check architecture ∈ family (qwen2/qwen3/qwen35 | llama/mistral)
    Local->>Local: DecoderGgufWeightLoader.loadToMapStreaming<br/>(packed Q8_0 / Q4_K weights, memory-mapped)
    Local->>Local: QwenNetworkLoader | LlamaNetworkLoader.fromWeights
    Local->>Local: OptimizedLLMRuntime(DIRECT), stop-token set
    Local-->>Provider: LocalModel (log [MODEL LOAD] … done in ms)
    Provider-->>Stage: model

    Note over Provider: releasing(): close after the stage<br/>caching() / --keep-models: keep resident
----

NOTE: The `STANDAPP_TINY_PROMPT=1` smoke path bypasses the pipeline and sends a
one-line prompt to the summariser through `LlamaChatLLMService` — a quick way
to verify download + inference without a repository.

== 6.5 Cloud API Request Flow

This scenario shows how an external client interacts with the cloud-api server via the OpenAI-compatible REST API.

[mermaid]
----
sequenceDiagram
    participant Client as HTTP Client<br/>(LlmClient / curl)
    participant Server as LocalAIServer<br/>(Ktor CIO)
    participant Handler as Route Handler
    participant Model as Response Builder

    Client->>Server: POST /v1/chat/completions<br/>{model, messages}
    Server->>Handler: dispatch request

    Handler->>Handler: parse JSON body
    Handler->>Handler: extract model & messages
    Handler->>Handler: find last user message

    Handler->>Model: build ChatCompletionResponse
    Model-->>Handler: response with choices & usage

    Handler-->>Server: respond(response)
    Server-->>Client: 200 OK<br/>{id, choices, usage}

    alt Error
        Handler-->>Server: 500 error JSON
        Server-->>Client: {"error": {...}}
    end
----
