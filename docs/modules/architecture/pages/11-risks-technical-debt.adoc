== 11.1 Technical Risks

[cols="1,2,2,2,1"]
|===
|ID |Risk |Impact |Mitigation |Priority

|TR-01
|*JDK 25 Toolchain Requirement*
The Vector API is still an incubator module and the native kernels need `--enable-preview` / `--enable-native-access`
|Breaking changes in future JDK versions; hosts without the toolchain need the foojay resolver to provision it
|Keep the JVM flags in one place (`standappJvmArgs`), monitor the JDK roadmap
|Medium

|TR-02
|*Model Compatibility*
GGUF format evolves, new quantization methods; `ModelFamily` accepts only `qwen2/qwen3/qwen35` and `llama/mistral`
|A user-supplied GGUF may be rejected or load slowly (non-packed path)
|Pin the catalog files (`ModelCatalog`), check architecture from the GGUF metadata before loading, size sanity check after download
|Medium

|TR-03
|*MCP Protocol Changes*
MCP is relatively new, spec may evolve
|Integration breaks with Claude updates
|Use official SDK, monitor protocol changes
|Low

|TR-04
|*Performance on Low-End Hardware*
CPU-only inference of a 3B model: ~0.3 s/token decode on an i7-9750H, plus ~40 s for the Qwen tool round
|A 300-token summary takes a couple of minutes; unusable on older machines
|Document requirements (§7.8); `preprocess { limit(60); firstMessageLine(120) }` keeps prompts short; `--commits git` skips the Qwen round; `REST_API` offloads to a server
|Medium

|TR-05
|*First-Run Download and Offline Use*
Both GGUFs (~0.6 GB + ~2.0 GB) are fetched from Hugging Face on first run; nothing is bundled
|Poor first-run experience on slow links; a cold cache fails outright behind a firewall or with `STANDAPP_OFFLINE=1` (exit code 4)
|Progress every 64 MB, unbounded request timeout, persistent cache (`STANDAPP_MODEL_CACHE_DIR`), local overrides (`--qwen-model` / `--llama-model`, `STANDAPP_*_MODEL_PATH`, `hf://` or `https://` URIs), `HF_TOKEN`; Docker mounts the cache as a volume
|Medium

|TR-06
|*Native Kernel Library Silently Unavailable*
`skainet-backend-native-cpu` extracts `libskainet_kernels.so` to `java.io.tmpdir` and `dlopen`s it. On a `noexec` temp directory (hardened containers, some CI runners) or without `--enable-native-access` the runtime falls back to the Panama/Vector-API kernels *without an error*
|Several-fold slower inference that looks like "the machine is slow"
|Docker sets `-Djava.io.tmpdir=/app/tmp` on an exec-capable tmpfs; the JVM flags are part of the launcher. Check `[STAGE/COMPLETE] … tok/s` against the documented numbers; consider logging the active kernel pack at startup
|Medium

|TR-07
|*Prefill as Slow as Decode*
The row-major FFM kernel processes batched prefill (`PrefillStrategy.Batched(64)`) row by row, so prefill costs ~0.3 s per prompt token — the same as decode
|A 1,000-token prompt (60 commits) spends ~5 minutes before the first token; retries on invalid JSON pay it again
|Keep prompts short (`preprocess`), cap `maxTokens`, `--keep-models` avoids reloading between retries; a true batched matmul path upstream is the real fix
|High

|TR-08
|*SKaiNET / SKaiNET-transformers API Stability*
Pinned at 0.53.0 through both BOMs; `AgentLoop`, `ChatTemplate`, `DecoderGgufWeightLoader`, `OptimizedLLMRuntime` and the `DataPipeline` DSL are pre-1.0. The 0.36 → 0.53 jump moved the decoder loader between artefacts and dropped kllama's Java facade
|Minor-version bumps may rename loaders, template classes or stage APIs
|BOM-pin both versions; verify each bump with the download smoke (`STANDAPP_TINY_PROMPT=1`) and a full two-model run; keep the composite build opt-in (`-PuseLocalTransformers=true`) for bisecting upstream changes
|Medium

|TR-09
|*Upstream Sampler Quadratic Without Top-k*
`sampleFromLogits(topK = 0, topP < 1)` sorts by insertion over the whole 128k Llama vocabulary — ~10 s per token measured
|Any caller that requests nucleus sampling without a finite top-k stalls
|`LlamaGenerateStage` always pairs `topP < 1` with `topK = 40` (llama.cpp default); temperature 0 / top-p 1 avoid the path. Report upstream
|Low

|TR-10
|*Qwen Skips or Botches the Tool Call*
A 0.6B model may answer in prose, call the tool with wrong arguments (validation failure) or emit the call twice
|Silent quality regression: the `[STAGE/FALLBACK]` path still produces a summary, so users may not notice the model is not doing its job; the failed round still costs ~40 s
|Thinking disabled, greedy sampling, explicit user prompt ("Pass days=7 as a number"), duplicate calls reuse the recorded result, `CommitBatch.source` records the path. Watch `[STAGE/FALLBACK]` in stderr; `--commits git` bypasses the stage; a larger Qwen via `--qwen-model` is a drop-in
|Medium

|TR-11
|*Memory Footprint*
The CLI runs with `-Xmx12g`; KV caches are capped at a 4096-token window and weights are memory-mapped, but `--keep-models` holds both models plus the FP32 activations
|OOM or heavy swapping on 8 GB machines, especially with `--keep-models`
|`ModelProvider.releasing()` (default) keeps peak memory at one model; document 16 GB for `--keep-models`; the Docker image uses `-Xmx6g` for the MCP server
|Low
|===

=== Debt Details

[cols="1,2,2,2"]
|===
|ID |Debt Item |Current State |Remediation

|TD-01
|*Summariser Reloaded per Retry*
|With the default `ModelProvider.releasing()` every generation attempt (JSON retry) reloads the Llama model; `--keep-models` is a manual workaround
|Keep the summariser resident for the duration of `RetryingSummarizeStage` while still releasing between the Qwen and Llama stages

|TD-02
|*Legacy `MCP_LLM_MODEL_PATH` Alias and `embedded` Shorthand*
|`MCP_LLM_MODEL_PATH` still maps to the Llama summariser; the benchmark's `BENCH_QXOTIC_MODEL=embedded` shorthand points at a cache file the SKAINET path no longer creates
|Migrate Docker/benchmark configs to `STANDAPP_LLAMA_MODEL_PATH`, retire the alias and the shorthand

|TD-03
|*MCP standup_summary Tool*
|Not implemented
|Add tool combining commits + LLM summarization

|TD-04
|*Platform Implementations*
|Return empty lists
|Implement or clearly document as unsupported

|TD-05
|*Logging*
|Minimal, inconsistent
|Add SLF4J throughout with configurable levels

|TD-06
|*Error Handling*
|Silent failures in GitClient
|Add proper error propagation and user-friendly messages

|TD-07
|*Cloud API Stub Backend*
|Server echoes user messages instead of running real inference
|Wire cloud-api server to an actual LLM backend (e.g., `LLMService` from llm module)
|===

== 11.4 Improvement Roadmap

=== Short Term (Next Release)

* [ ] Implement `standup_summary` MCP tool
* [ ] Add streaming support to MCP responses
* [ ] Improve error messages
* [ ] Wire cloud-api server to real LLM backend

=== Medium Term

* [ ] Keep the summariser resident across parse retries (TD-01)
* [ ] Add integration tests
* [ ] Unify configuration approach (env vars vs system properties)
* [ ] Log the active kernel pack at startup so a silent native-library fallback is visible (TR-06)

=== Long Term

* [ ] Native platform support (beyond stubs)
* [ ] HTTP transport option for MCP
* [ ] Model management tooling (pre-warm / verify the cache, list downloaded models)
* [ ] Batched prefill matmul upstream (removes TR-07)
