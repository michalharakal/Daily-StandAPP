= PRD: SKaiNET-transformers — Fast Llama Runtime & Agent Loop
:navtitle: PRD — SKaiNET-transformers

Product requirements for the SKaiNET-transformers repository
(https://github.com/SKaiNET-developers/SKaiNET-transformers[SKaiNET-developers/SKaiNET-transformers],
artifacts `sk.ainet.transformers:*`) within the upstream performance program.
Companion documents: xref:prd-skainet.adoc[PRD — SKaiNET core] and
xref:integration-release-plan.adoc[Integration & Release plan].

== Goal

Make the llama runtime and agent loop fast enough to complete the
Daily-StandAPP benchmark (program phase "benchmark-complete": full 15-case
matrix, zero timeouts at a 180 s budget), then reach Deliverance-class CPU
parity, and give the agent path production ergonomics — while converging on
the program's single-execution-IR architecture (spike-gated; see the
integration plan).

== Non-goals

* Kernel implementations (GEMM/GEMV, quantized compute) — SKaiNET core.
* MLIR/StableHLO lowering and IREE tooling — SKaiNET core / embedded.
* Hand-written GPU kernels — superseded by the compiler track.

== Current state (verified; file:line refs on `develop` post-#238)

* `KLlamaJava.loadGGUF`: `QuantPolicy.NATIVE_OPTIMIZED`,
  `OptimizedLLMMode.DIRECT`, never `compile()` (KLlamaJava.kt:69,85) —
  quantized weights, FP32 activations, eager module-tree path.
* KV cache on the production path is `AppendKVCache`: `ops.concat` of the
  *entire* growing K and V every token × every layer (KVCache.kt:93-98) —
  O(seqLen) realloc+copy per step. A contiguous/off-heap design
  (`KvCacheJvm`: `OffheapKvCache`/`PagedKvCache`) exists but only the
  deprecated `LlamaRuntime` uses it.
* `fusedDecodeAttention` engages only for seqLen == 1 decode and still copies
  the full K/V buffers each token × layer (`attn.fused_copy`,
  MultiHeadAttention.kt:470-475).
* lm_head is a full `[dim × vocab]` dense matmul every decode step
  (`VoidDense`, PhaseProfile tag `lm_head`); tied embeddings resolved at
  load time.
* Sampling is temperature-only everywhere; `topP` is accepted in API shapes
  and silently dropped (SkaiNetChatModel.kt:34-38).
* Agent loop: `runtime.reset()` + full conversation re-render + re-prefill
  *every round* (AgentLoop.kt:120-128); no prefix/KV-reuse infrastructure
  exists.
* Batched prefill (#226/#238) is merged, default still `Autoregressive`; the
  latest published release (0.36.1) predates the merge.
* Two profiling docs referenced from code comments
  (`docs/upstream/A2-PROFILE.md`, `position_collapse_bug.md`) do not exist in
  the tree; `weight-quantization.adoc` contradicts the 0.36.0 kernel reality.
* Measured (Daily-StandAPP benchmark, M-series CPU, Llama 3.2 1B Q8_0):
  ~1.8 tok/s decode; 225–492 s per 512-token generation; agent tool-calling
  template ≈ 87 s to first token pre-#238.

Streams: S2 = runtime, S3 = agent/API, S4 = compiler track (shared with
core). Spike-gated tasks do not start before the SPIKE-1 verdict (see
integration plan).

== Success metrics

* Phase-1 gate: full 15-case Daily-StandAPP SKAINET matrix completes with
  0 timeouts at `BENCH_TIMEOUT_MS=180000`.
* Phase-2 gate: SKAINET p50 ≤ Deliverance p50 (31 s) on the same matrix.
* Agent demo gate: tool-calling CLI first token < 10 s, full answer < 60 s.
* No eager-vs-traced numerics divergence in equivalence suites at any release.
