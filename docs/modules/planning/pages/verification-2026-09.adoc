== Measured speeds (this laptop)

* Llama-3.2-3B-Instruct Q4_K_M, idle machine, short context: ≈ 0.3 s per token
  for both decode and prefill — the row-major FFM kernel processes a batched
  prefill row by row, so prompt length dominates: a 400-token prompt costs
  ≈ 2 min before the first token (step 7: 397 tokens → 130 s).
* Long context (≈ 2,100-token prompts, steps 8–9) measured while the Antora
  Docker build shared the CPU and the JVM sat close to swap (RSS ≈ 14 GB):
  prefill 0.6–0.8 s per token, decode 4–18 s per token. Treat these as an upper
  bound; re-measure on an idle machine before quoting them.
* Qwen3-0.6B Q8_0 tool round (≈ 330-token rendered prompt, thinking off, one
  round): 40–55 s.
* Practical guidance: keep windows small (`--days 1..7`), rely on the CLI's
  `shortIds(7); firstMessageLine(120); limit(60)`, and raise `--max-tokens` for
  JSON output over many commits.

== Findings fed back into the code

. Top-p must be paired with a finite top-k on this SKaiNET version (see step 4).
. Qwen3-0.6B sometimes emits the same `<tool_call>` twice in one turn; the
  tool reuses its recorded result for an identical repeat.
. The `[SKaiNET] Using SIMD-accelerated …` banners are printed on stdout by the
  library; the CLI diverts `System.out` for the whole run so stdout carries only
  the summary.
. JSON output for many commits overruns 512 tokens on a 3B model; the CLI prints
  a `[STAGE/WARN]` budget hint suggesting `--max-tokens`.
