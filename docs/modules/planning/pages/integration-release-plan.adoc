= Integration & Release Plan — SKaiNET Upstream Program
:navtitle: Integration & releases

The gluing layer between xref:prd-skainet.adoc[PRD — SKaiNET core] and
xref:prd-skainet-transformers.adoc[PRD — SKaiNET-transformers]: interface
contracts, the architecture spike that fixes the program's direction, glue
tasks, the release train, and the parallel-stream map. Daily-StandAPP serves
as the program's end-to-end acceptance testbed.

== Architecture decision (spike-gated)

Convergence target: the `network {}` DSL is the *authoring* layer; the traced
DAG is the *single execution IR* with two backends —

. in-process `ComputeGraphExecutor` ("eager by graph"; same
  `DefaultCpuOps`/Panama kernels, plus graph-level fusion via
  `LLMFusionPass`/`LLMFusedOpHandlers`), and
. DAG → StableHLO (`skainet-compile-hlo`) → IREE (local-task CPU HAL, later
  Metal), weights via `.irpa`.

Rationale: the dual-numerics bug class (position collapse, RoPE dual-path,
`fusedDecodeAttention` recording escapes) exists *because* eager and traced
paths diverge; a single IR eliminates it and makes every optimization serve
CPU and GPU once. Commitment is **gated on SPIKE-1 evidence** — eager-only
optimizations (TX-4 wiring, TX-5) do not start before the verdict.

== SPIKE-1 — Execution-architecture spike

Time-boxed (~2 weeks), the program's **first task**, joint core+TX, stream S4.

Scope:

. Run one llama/gemma decode step through `ComputeGraphExecutor` with
  externalized KV state (a minimal hack of the `[1]`-shape OPTIMIZED trace is
  acceptable for the spike).
. Compile the same graph via `dag2hlo` → `iree-compile` local-task CPU HAL
  and run it (the FunctionGemma `.vmfb` + `.irpa` assets from SKaiNET-embedded
  are the starting point).
. Measure both against the eager DIRECT baseline (TX-1 harness shapes) and
  check greedy parity.

**Decision criteria (fixed before measuring):** if graph-executor *or*
IREE-CPU decode is within **1.5×** of eager (or faster) AND
KV-state-as-graph-I/O shows no blocker → **graph-first**: TX-5 cancelled,
TX-4 reduces to kernel work (CORE-2), R2 scope shifts to graph-path
productization. Otherwise → **bridge-then-retire**: TX-4/TX-5 proceed as
specced; the compiler track continues in S4 at lower priority. Verdict is
recorded in this document.

== Interface contracts

Frozen during the R1 window; owned by core, versioned in its docs; additive
changes only within the release train.

[cols="1,2,4", options="header"]
|===
| ID | Name | Content

| CT-A
| Kernel SPI stability
| `backend-api` matmul/GEMM signatures (`m,n,k`, strides) and dispatch
semantics stable across the train. Consumers: TX-2, TX-4, all of S1.

| CT-B
| Zero-copy views
| `ops.narrow`/slice guarantee (no hidden copies) that TX KV buffer-direct
reads rely on. Produced by CORE-3; consumed by TX-3/TX-5.

| CT-C
| Stateful graph I/O
| Naming/shape convention for KV state-in/state-out. Co-signed by CORE-4
(core) and TX-3/TX-10 (transformers) *before* either implements.

| CT-D
| Version pairing + soak policy
| TX pins core via `sk.ainet:skainet-bom`; pre-1.0 minor bumps; behavior
flips (e.g. prefill default) ship opt-in one release before default.
|===

== Parallel stream map

Four workstreams; day-1-startable tasks in bold.

[cols="1,3,4", options="header"]
|===
| Stream | Scope | Order

| S1
| Core kernels (strategy-neutral: kernels serve eager, graph executor, and
IREE ukernel comparisons alike)
| **CORE-1** → CORE-2; **CORE-3**

| S2
| TX runtime
| **TX-1** → TX-2 → TX-3 → (TX-4/TX-5 only on bridge verdict) → TX-6

| S3
| TX agent/API
| **TX-7**, **TX-9**; then TX-8 (waits on TX-3 from S2)

| S4
| Compiler/IREE (joint)
| **G-1 → SPIKE-1** (the program's first decision point); then **CORE-4**,
**CORE-6** (against the existing FunctionGemma `.vmfb`), CORE-5; then TX-10
(waits on TX-3 + CORE-4)
|===

Cross-stream sync points: SPIKE-1 verdict (gates TX-4/TX-5, fixes R2 scope);
CT-C sign-off (S2+S4, early); TX-3 landing (unblocks TX-8/TX-10); each
release gate.
